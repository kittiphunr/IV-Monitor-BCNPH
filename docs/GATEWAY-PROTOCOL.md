# โปรโตคอล Host-Gateway ↔ พีซี (Gateway Protocol v1)

เป็นโปรโตคอลคนละชั้นกับ ESP-NOW **Protocol v3** (Station↔Host) ซึ่งไม่เปลี่ยนแม้แต่ไบต์
ชุดทดสอบ `bash tools/gateway-test/run.sh` รันเฟิร์มแวร์จริงคู่กับเซิร์ฟเวอร์จริงเพื่อตรวจเอกสารนี้ไม่ให้เพี้ยนจากโค้ด

## คำขอเดียวต่อวินาที

Host เป็นฝ่ายเริ่มเสมอ ไม่รับการเชื่อมต่อขาเข้า

```
POST /api/ingest HTTP/1.1
Content-Type: application/json
X-Gateway-Token: <รหัส ถ้าตั้งไว้>        ← ตั้งที่ Setup Portal และ --token ของเซิร์ฟเวอร์

{ ...สถานะ... }
```

ตอบ `200 text/plain` เป็นข้อความทีละบรรทัด `400` ถ้าข้อมูลผิดรูป `403` ถ้ารหัสไม่ตรง
Host ถือว่า 200 เท่านั้นคือส่งสำเร็จ

## ขาขึ้น: JSON สถานะ

ชื่อฟิลด์ของเตียงตรงกับที่หน้าเว็บเดิมของ Host-OLED อ่านทุกตัว เซิร์ฟเวอร์ส่งต่อให้หน้าเว็บได้โดยไม่แปลง

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `v` | string | เวอร์ชันเฟิร์มแวร์ เช่น `1.0.0-GW` |
| `host` | string | MAC ของ Host ไม่มีโคลอน 12 ตัวอักษรฐานสิบหก ใช้แยก Host ที่พีซี |
| `ack` | uint | เลขลำดับคำสั่งล่าสุดที่ **ทำเสร็จแล้ว** (0 = ยังไม่เคย) |
| `up` | uint | มิลลิวินาทีนับจากเปิดเครื่อง |
| `resetReason` | string | สาเหตุการรีบูตครั้งล่าสุด |
| `count` | uint | จำนวนเตียงที่เปิดใช้ (1..8) |
| `ip`, `rssi`, `channel` | | ที่อยู่ สัญญาณเราเตอร์ ช่อง ESP-NOW |
| `bat`, `batPct` | | แบตเตอรี่ของ Host (0 V = ไม่มีวงจรวัด) |
| `snooze` | bool | กำลังพักเสียง |
| `linkWeakPct`, `syncFail`, `heardBeyond`, `pushFail` | | วินิจฉัยลิงก์ |
| `stations[]` | array | เตียงละหนึ่งก้อน เรียงตามเลขเตียง 1..`count` |

ก้อนเตียง: `id online running rssi link idConflict mac rxTotal battery totalDrops volumeMl flowRateHr
msSinceLastDrop targetRate planVolume dropFactor patientName alertCode nearEndPct nearEndAck caseActive caseStart`

ค่าตั้งเตียง (`targetRate planVolume dropFactor patientName nearEndPct`) ส่งกลับทุกวินาทีด้วย
เพื่อให้พีซีเรียนรู้ค่าจาก Host ไม่ต้องเก็บต้นฉบับเอง

ขนาดจริง 8 เตียงราว 3 KB

## ขาลง: ข้อความทีละบรรทัด

```
T <epoch>                                       เวลาปัจจุบัน UTC (บรรทัดแรกเสมอ)
C <seq> <เตียง> rate= vol= df= near= name=      ตั้งค่าเตียง ส่งเฉพาะคีย์ที่เปลี่ยน
R <seq> <เตียง>                                  เริ่มถุงใหม่
A <seq> <เตียง>                                  รับทราบเตือน
N <seq> 0 count=<n>                             จำนวนเตียงที่เปิดใช้
```

- `name` เข้ารหัสเปอร์เซ็นต์ (UTF-8) เหลือ ≤ 63 ไบต์
- ช่วงค่าที่ Host รับ: `rate` 0–1000, `vol` 0–10000, `df` ∈ {10,15,20,60}, `near` 50–95, `count` 1–8
  ค่านอกช่วงถูกข้ามทีละคีย์ **แต่คำสั่งยังถูก ack** ไม่งั้นพีซีส่งซ้ำไม่จบ
- บรรทัดที่แกะไม่ได้ถูกข้ามเงียบ ๆ ไม่ทำให้เครื่องล้ม

## ความน่าเชื่อถือของคำสั่ง (at-least-once + ข้ามซ้ำ)

1. พีซีให้คำสั่งทุกคำสั่งมี `seq` เพิ่มทีละ 1 ต่อ Host
2. พีซีแนบคำสั่งที่ยังไม่ถูก ack ในคำตอบทุกรอบ (สูงสุด 8 บรรทัด)
3. Host เข้าคิวเฉพาะ `seq` ที่ใหญ่กว่าที่เคยเข้าคิวแล้ว จึงไม่ทำซ้ำ
4. เธรดส่งแค่ใส่คิว (ความจุ 12) `loop()` เป็นคนลงมือทำ แล้วตั้ง `ack = seq`
   เพราะการแก้ `stations[]` และ NVS ต้องอยู่เธรดเดียวกับตรรกะเตือน
5. พีซีลบคำสั่งที่ `seq ≤ ack` และเลือก `seq` ถัดไป = `max(ของเดิม, ack+1)` เพื่อให้ตามทันเมื่อพีซีรีสตาร์ต
6. คำสั่งที่ค้างเกิน 10 นาทีถูกทิ้ง
7. คิว Host เต็ม → ข้ามส่วนที่ล้น (ไม่นับว่ารับ) พีซีส่งซ้ำรอบหน้า

## ฝั่งหน้าเว็บ (พีซี ↔ เบราว์เซอร์)

เซิร์ฟเวอร์เลียนแบบ API เดิมของ Host-OLED เพื่อใช้หน้าเว็บเดิมได้ทั้งหน้า

| Endpoint | ความต่างจาก Host-OLED |
|---|---|
| `GET /api/data` | เพิ่ม `hostOnline`, `gatewayId`, `gatewayAgeS` Host เงียบเกิน 5 วินาที = ทุกเตียงออฟไลน์ |
| `GET /api/logs?station=` | อ่านจาก SQLite ถุงปัจจุบัน ล่าสุด 600 รายการ (เดิม 60) |
| `GET /api/logs/csv?station=` | หัวคอลัมน์เดิมทุกตัว |
| `POST /api/stations/{config,reset,ack,set}` | ตรวจช่วงค่าแล้วเข้าคิวคำสั่ง ตอบทันที ไม่รอ Host |
| `POST /api/time/set` | รับแต่ไม่ใช้ พีซีเป็นเจ้าของเวลา |
| `GET /api/hosts` | ใหม่ รายการ Host สำหรับตัวเลือกในหน้าเว็บ |
| `/api/wifi/*` | ไม่มี ถอดปุ่มออกจากหน้าเว็บแล้ว |
