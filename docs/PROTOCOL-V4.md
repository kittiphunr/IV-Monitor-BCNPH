# โปรโตคอล ESP-NOW v4 (Station แบบบาง)

ใช้ระหว่าง **Station-Thin** กับ **Host-TFT-Gateway** เท่านั้น เป็นคนละชนิดกับ Protocol v3 ของสายอื่น
(v3 ยังล็อกให้ตรงกันทุกไบต์ใน 8 สายเฟิร์มแวร์ และไม่เปลี่ยน)
นิยามโครงสร้างอยู่ใน `protocol_v4.h` ซึ่งต้องเหมือนกันทุกไบต์ในสองโฟลเดอร์ ตรวจด้วย `bash tools/v4-test/run.sh`

## แนวคิด

| | Protocol v3 (สายหลัก) | Protocol v4 (สายบาง) |
|---|---|---|
| Station ส่งขึ้น | หยดสะสม + **อัตราไหลที่คำนวณเอง** + เวลาจากหยดล่าสุด + แบตเตอรี่ (23 ไบต์) | หยดสะสม + เวลาจากหยดล่าสุด + ธง + แบตเตอรี่ (14 ไบต์) |
| Host ส่งลง | ค่าตั้ง + รหัสเตือน + เวลา (20 ไบต์) | **ผลคำนวณทั้งหมด** + ค่าตั้ง + รหัสเตือน + เวลา (32 ไบต์) |
| อัตราไหลคำนวณที่ | Station (หน้าต่าง 8 หยด) | Host (`rate_estimator.h`) |
| ปริมาตร % เวลาที่เหลือ | Station คำนวณเองบนจอ | Host คำนวณ Station แสดง |
| สายพับ / ใกล้หมด / ครบแผน | Station ตัดสินเองได้ทันที | Host ตัดสินที่เดียว |
| Host หาย | จอ Station ยังแสดงอัตราและเตือนสายพับเองได้ | จอขึ้น **NO HOST** เหลือหยดสะสมกับปริมาตรที่ให้แล้ว |

## แพ็กเก็ตขึ้น `struct_up_v4` (14 ไบต์ วินาทีละใบต่อเตียง)

| ฟิลด์ | ขนาด | ความหมาย |
|---|---|---|
| `magic` | 1 | `0xA4` |
| `stationId` | 1 | เลขเตียง 1–8 |
| `flags` | 1 | bit0 กำลังนับ · bit1 กดรับทราบเตือนใกล้หมด · bit2 เซนเซอร์เคยจับหยด · bit3 เซนเซอร์ยังจับหยดไม่ได้ · bit4–7 ต้องเป็น 0 |
| `seq` | 1 | เพิ่มทีละ 1 |
| `totalDrops` | 4 | หยดสะสม (เก็บลง NVS กู้ได้หลังรีบูต) |
| `msSinceLastDrop` | 4 | มิลลิวินาทีจากหยดล่าสุด ณ ตอนส่ง (0 = ยังไม่มีหยด) |
| `batteryMv` | 2 | มิลลิโวลต์ (0 = ไม่มีวงจรวัด) |

## แพ็กเก็ตลง `struct_down_v4` (32 ไบต์ วินาทีละใบต่อเตียง เฉลี่ยช่องเวลา)

| ฟิลด์ | ความหมาย |
|---|---|
| `magic` = `0xA5`, `stationId` | |
| `flags` | bit0 รับทราบเตือนใกล้หมดแล้ว · bit1 Host ได้ยินเตียงนี้ · bit2 เวลาเป็นเวลาจริง · bit3 มีแผนปริมาตร · bit4 อัตราไหลคำนวณได้จริง |
| `alertCode` | 0–5 รหัสภายใน Host (เช่น เตียงหาย) ถูกแปลงเป็น 0 ก่อนส่ง |
| `resetSeq` | เปลี่ยนค่า = เริ่มถุงใหม่ Station ล้างยอดหยด |
| `dropFactor`, `nearEndPct`, `hostChannel`, `epochTime` | |
| `rateHr`, `targetRateHr`, `planMl`, `infusedMl` | mL/h และ mL |
| `minutesLeft` | `0xFFFF` = คำนวณไม่ได้ |
| `infusedPct` | 0–100 (ใช้ได้เมื่อมีธง PLAN_SET) |

กรองแพ็กเก็ตด้วย **ความยาวและไบต์แรก** ทุกครั้ง แพ็กเก็ต v3 (23 และ 20 ไบต์) หรือของอุปกรณ์อื่นจึงถูกทิ้งทันที
Host ยังตรวจช่วงค่า (ธงสำรอง แบตเตอรี่เกินจริง เวลาจากหยดล่าสุดที่ไม่มีหยด) ก่อนรับ

## ทำไมต้องส่งเวลาจากหยดล่าสุดด้วย

ถ้าส่งแค่จำนวนหยด Host เห็นแต่ "กี่หยดต่อวินาที" อัตราจะหยาบและแกว่งมาก (ที่ 3 mL/h คือหนึ่งหยดต่อนาที
จึงเห็นเป็น 0 บ้าง 1 บ้าง) รุ่นก่อน Station 7.7.3 เคยคำนวณแบบนี้และเตือนผิดบ่อย

`msSinceLastDrop` ทำให้ Host ย้อนไปหา **เวลาแน่นอนของหยดหนึ่ง** ในฐานเวลาของตัวเองได้ทุกแพ็กเก็ต (เรียกว่า "จุดยึด")
หยดระหว่างสองจุดยึดไม่รู้เวลาเป็นรายหยด แต่รู้จำนวนแน่นอน (ผลต่างของ `totalDrops`)

```
อัตรา = (หยดระหว่างจุดยึดแรกถึงสุดท้าย / dropFactor) × 3,600,000 / เวลาระหว่างสองจุด (ms)
```

ทั้งเศษและส่วนเป็นค่าแน่นอน จึงแม่นเท่ากับที่ Station เคยคำนวณจากเวลาของทุกหยด และแพ็กเก็ตหายไม่ทำให้ผิด
ผลทดสอบ (`tools/v4-test/estimator_test.cpp`): ต่างจากวิธีเดิมของ Station ไม่เกิน 0.4% ที่ 3–1200 mL/h
รวมกรณีแพ็กเก็ตหาย 50%

กติกาเดียวกับหน้าต่างของ Station 7.7.3: ไม่เกิน 8 หยด ล้างเมื่อหยุดชั่วคราว/ตัวนับถอยหลัง/ห่างเกิน 300 วินาที
และเมื่ออัตราเปลี่ยนก้าวกระโดดเกิน 3 เท่า

## ข้อควรรู้เมื่อเลือกสายนี้

- **Host หายแล้วจอ Station จำกัด** ไม่มีอัตราไหล % เวลาที่เหลือ และรหัสเตือน (จอขึ้น NO HOST สีส้ม ไม่ใช่ NORMAL สีเขียว)
  ถ้าวอร์ดต้องการให้เครื่องข้างเตียงเฝ้าได้ลำพัง ให้ใช้ Station สายหลัก
- Station ใช้ได้กับ Host-TFT-Gateway เท่านั้น ใช้ปนกับ Host รุ่นอื่นไม่ได้ (คุยกันไม่รู้เรื่อง ไม่ใช่เสียหาย)
- Host ต้องมีเวลาของตัวเอง (millis) ต่อเนื่อง ไม่ต้องตรงกับ Station
