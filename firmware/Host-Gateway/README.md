# 1.0.1-GW — แก้บั๊ก: สุนัขเฝ้าบ้านต้องทำงานทุกครั้งที่เปิดเครื่อง

**อาการ** ใน `setup()` วงเล็บ `}` ที่ควรปิดบล็อก `if (wakeup_reason == ...)` ของการปลุกจาก deep sleep ไปอยู่ท้ายสามบรรทัด
`bootResetReason = esp_reset_reason()`, `Serial.printf("[boot] reset reason ...")` และ `setupLoopWatchdog()`
สามบรรทัดนี้จึงตกอยู่ในบล็อกนั้นและทำงานเฉพาะตอนปลุกจาก deep sleep ตอนเสียบไฟปกติ (cold boot)
สุนัขเฝ้าบ้านไม่ถูกเปิดและไม่มีการบันทึกสาเหตุรีบูต ขัดกับเจตนาของรุ่น 4.8.0 ที่ว่าค้างจริงต้องรีบูต

**แก้** ปิดบล็อก `if` ทันทีหลังรอปุ่มกดค้าง แล้วเรียกสามบรรทัดนั้นทุกครั้งที่เปิดเครื่อง
เพิ่ม `feedWatchdog()` ก่อนและหลังเสียงต้อนรับกับ `delay(1400)` ใน `setup()` ส่วนที่เหลือของ `setup()` ไม่มีการรอแบบบล็อกยาวเกิน
`LOOP_WDT_TIMEOUT_S` (8 วินาที) เส้นทางปิดเครื่อง `stopLoopWatchdog()` ไม่เปลี่ยน

**พิสูจน์** ตัวจำลอง (`esp_task_wdt.h` นับการสมัคร/ป้อน/ถอน และช่วงที่นานที่สุดที่ไม่ป้อน) เรียก `setup()` จริงทั้งแบบ cold boot และแบบปลุก (`ESP_SLEEP_WAKEUP_EXT0`)
ต้องสมัครครั้งเดียวทั้งสองแบบ ก่อนแก้ cold boot ได้ 0 ครั้ง ทดสอบใน `tools/gateway-test/driver.cpp` และ `tools/v4-test/host_driver.cpp`

**ข้อจำกัด** เฟิร์มแวร์นี้ **ยังไม่ได้ทดสอบบนฮาร์ดแวร์จริง** ตรวจด้วยเครื่องมือจำลองบน PC เท่านั้น

# เครื่องส่วนกลางรุ่นเกตเวย์ v1.0.0-GW

แตกจาก Host-OLED 4.9.1 เพื่อแก้ปัญหาเดียว: **Host ทำงานหนักเกินไป**
รุ่นนี้ไม่เปิดเว็บเอง เหลือแค่รับเตียง ตัดสินเตือน แจ้งเตือนหน้างาน และส่งสรุปขึ้นพีซีวินาทีละหนึ่งก้อน

อ่านเหตุผลและข้อจำกัดที่ [`docs/GATEWAY-DESIGN.md`](../../docs/GATEWAY-DESIGN.md)
รายละเอียดข้อความที่ส่งที่ [`docs/GATEWAY-PROTOCOL.md`](../../docs/GATEWAY-PROTOCOL.md)

> **ยังไม่ได้ทดสอบบนฮาร์ดแวร์จริง** ตรวจด้วยตัวจำลองบน PC เท่านั้น (`bash tools/gateway-test/run.sh`)

## ฮาร์ดแวร์

เหมือน Host-OLED ทุกขา (ESP32-S3 + SH1106 + Buzzer) สลับบอร์ดข้ามสองรุ่นได้โดยไม่ต้องแก้สายไฟ
ใช้คู่กับ Station สายใดก็ได้ Protocol v3 ไม่เปลี่ยน

## ติดตั้งครั้งแรก

1. แฟลช `Host-Gateway.ino` (ไฟล์ `HostScreen.h` เปิดเป็นแท็บเดียวกันใน Arduino IDE)
2. เครื่องยังไม่มีรหัสเราเตอร์ จึงเปิด Wi-Fi ชื่อ **`IV-Gateway-Setup`** (รหัส `12345678`) จอขึ้น `SETUP 192.168.4.1`
3. ต่อมือถือเข้า Wi-Fi นั้น เปิด `http://192.168.4.1` กรอก
   - ชื่อและรหัส Wi-Fi ของเราเตอร์
   - ที่อยู่ IP ของพีซีที่รัน `server/PC-Dashboard` และพอร์ต (ปริยาย 8080)
   - รหัสเกตเวย์ ถ้าตั้ง `--token` ที่พีซี
4. กดบันทึก เครื่องรีสตาร์ตเข้าโหมดปกติ จอขึ้น `PC OK <ip>` เมื่อพีซีรับข้อมูลแล้ว

โหมดตั้งค่าเปิดนานสุด 10 นาทีแล้วรีสตาร์ตเอง

## ตั้งค่าใหม่ภายหลัง

กดปุ่มเปลี่ยนหน้า (GPIO 5) **ค้างไว้ตอนเปิดเครื่อง 3 วินาที** จอขึ้น `WIFI CLEARED` แล้วปล่อย
เครื่องล้างค่าเครือข่ายและเข้าโหมดตั้งค่า (ค่าตั้งเตียงใน NVS ไม่ถูกลบ)

## ข้อความบนจอ

| ข้อความ | ความหมาย |
|---|---|
| `PC OK 192.168.1.10` | พีซีรับข้อมูลปกติ |
| `PC LINK DOWN` | ต่อเราเตอร์ได้ แต่พีซีไม่ตอบ (พีซีดับ ไฟร์วอลล์ ที่อยู่ผิด) |
| `NO ROUTER` | ต่อเราเตอร์ไม่ได้ ลองใหม่เองเรื่อย ๆ |
| `NO PC SET` / `NO WIFI SET` | ยังไม่ได้ตั้งค่า |
| `SETUP …` | โหมดตั้งค่าครั้งแรก |

มุมขวาบนของหัวจอ: `PC` = ลิงก์พีซีปกติ `--` = ขาด ถัดไปเป็นแท่งสัญญาณเราเตอร์

## สิ่งที่ต่างจาก Host-OLED

| | Host-OLED | Host-Gateway |
|---|---|---|
| หน้าเว็บ / REST / CSV | ที่เครื่อง | ที่พีซี |
| Access Point | มี (สำรอง) | ไม่มี (ยกเว้นโหมดตั้งค่าครั้งแรก) |
| ล็อกรายนาที | ใน RAM 60 รายการต่อเตียง | ที่พีซี ไม่จำกัด (SQLite) |
| เวลา | พยาบาลเปิดเว็บเพื่อซิงก์ | มาจากพีซีอัตโนมัติ |
| ตั้งค่าเตียง | จากหน้าเว็บที่เครื่อง | จากหน้าเว็บที่พีซี (Host เก็บใน NVS ด้วย) |
| เตือนหน้างานเมื่อพีซี/เราเตอร์ล่ม | – | ทำงานครบ |

ตรรกะการวัด การเตือน Sync และโครงสร้างแพ็กเก็ตย้ายมาโดยไม่แก้
`HostScreen.h` ต่างจาก Host-OLED แค่จุดที่เคยแสดงที่อยู่หน้าเว็บ

## ข้อควรระวัง

- เมื่อพีซีดับ **เปลี่ยนค่าเตียงไม่ได้** เพราะการตั้งค่ามาทางพีซีเท่านั้น ค่าเดิมที่ตั้งไว้ยังใช้ตัดสินเตือนต่อ
- จำนวนเตียงต่อเครื่องยังเป็น 8 ดูข้อจำกัดข้อ 1–2 ใน `docs/GATEWAY-DESIGN.md`
- ขณะเราเตอร์ล่ม การลองต่อใหม่ทำให้วิทยุกระโดดช่องชั่วคราว แพ็กเก็ตจากเตียงอาจหาย ใช้ backoff 10 วินาที → 5 นาทีเพื่อลดผลกระทบ **ต้องวัดบนบอร์ดจริงก่อนใช้งานในวอร์ด**
