# 1.1.1-TG — แก้บั๊ก: สุนัขเฝ้าบ้านต้องทำงานทุกครั้งที่เปิดเครื่อง

**อาการ** ใน `setup()` วงเล็บ `}` ที่ควรปิดบล็อก `if (wakeup_reason == ...)` ของการปลุกจาก deep sleep ไปอยู่ท้ายสามบรรทัด
`bootResetReason = esp_reset_reason()`, `Serial.printf("[boot] reset reason ...")` และ `setupLoopWatchdog()`
สามบรรทัดนี้จึงตกอยู่ในบล็อกนั้นและทำงานเฉพาะตอนปลุกจาก deep sleep ตอนเสียบไฟปกติ (cold boot)
สุนัขเฝ้าบ้านไม่ถูกเปิดและไม่มีการบันทึกสาเหตุรีบูต ขัดกับเจตนาของรุ่น 4.8.0 ที่ว่าค้างจริงต้องรีบูต

**แก้** ปิดบล็อก `if` ทันทีหลังรอปุ่มกดค้าง แล้วเรียกสามบรรทัดนั้นทุกครั้งที่เปิดเครื่อง
เพิ่ม `feedWatchdog()` ก่อนและหลังเสียงต้อนรับกับ `delay(1400)` ใน `setup()` ส่วนที่เหลือของ `setup()` ไม่มีการรอแบบบล็อกยาวเกิน
`LOOP_WDT_TIMEOUT_S` (8 วินาที) เส้นทางปิดเครื่อง `stopLoopWatchdog()` ไม่เปลี่ยน

**พิสูจน์** ตัวจำลอง (`esp_task_wdt.h` นับการสมัคร/ป้อน/ถอน และช่วงที่นานที่สุดที่ไม่ป้อน) เรียก `setup()` จริงทั้งแบบ cold boot และแบบปลุก (`ESP_SLEEP_WAKEUP_EXT0`)
ต้องสมัครครั้งเดียวทั้งสองแบบ ก่อนแก้ cold boot ได้ 0 ครั้ง ทดสอบใน `tools/gateway-test/driver.cpp` และ `tools/v4-test/host_driver.cpp`

**ข้อจำกัด** เฟิร์มแวร์นี้ **ยังไม่ได้ทดสอบบนฮาร์ดแวร์จริง** ตรวจด้วยเครื่องมือจำลองบน PC เท่านั้น

# เครื่องส่วนกลางจอ TFT 2.8" รุ่นเกตเวย์ v1.0.0-TG

คู่กับ **Station-Thin** ผ่าน Protocol v4: Host คำนวณอัตราไหล ปริมาตร % เวลาที่เหลือ และตัดสินเตือน
แล้วส่งผลกลับให้จอ Station แสดง และส่งสรุปขึ้นพีซีแบบเดียวกับ Host-Gateway (ไม่เปิดเว็บเอง)

อ่านหลักการที่ [`docs/PROTOCOL-V4.md`](../../docs/PROTOCOL-V4.md) และ [`docs/GATEWAY-DESIGN.md`](../../docs/GATEWAY-DESIGN.md)

> **ยังไม่ได้ทดสอบบนฮาร์ดแวร์จริง** ตรวจด้วยตัวจำลองบน PC (`bash tools/v4-test/run.sh`)

## ที่มา

| ส่วน | มาจาก |
|---|---|
| จอ TFT ตรรกะเตือน ปุ่ม แบตเตอรี่ | Host-TFT28 4.9.1-TFT (ไม่แก้) |
| ลิงก์ขึ้นพีซี คำสั่งมีเลขลำดับ หน้าตั้งค่าครั้งแรก | Host-Gateway 1.0.0-GW (ไม่แก้) |
| รับ Protocol v4, ตัวคำนวณอัตราไหล, ส่งผลลง Station | ใหม่ในรุ่นนี้ |

`bash tools/gateway-sync/run.sh` เทียบฟังก์ชันที่ยกมากับต้นฉบับทีละบรรทัด

## ติดตั้งครั้งแรก

เหมือน Host-Gateway: เครื่องเปิด Wi-Fi ชื่อ `IV-Gateway-Setup` (รหัส `12345678`) ให้ต่อมือถือแล้วเปิด `http://192.168.4.1`
กรอกชื่อ/รหัส Wi-Fi ของเราเตอร์ ที่อยู่พีซี พอร์ต (ปริยาย 8080) และรหัสเกตเวย์ (ถ้ามี) กดบันทึกแล้วเครื่องรีสตาร์ต
ตั้งค่าใหม่ภายหลังด้วยการกดปุ่มเปลี่ยนหน้าค้างตอนเปิดเครื่อง 3 วินาที
พีซีใช้ `server/PC-Dashboard` ตัวเดียวกับ Host-Gateway

## ฮาร์ดแวร์

เหมือน Host-TFT28 ทุกขา (ESP32-S3 N16R8 + ST7789V 2.8" + Buzzer)

## ตรวจระดับแบตเตอรี่ (1.1.0-TG)

Host ตรวจ **แบตเตอรี่ของตัวเองและของทุกเตียง** ด้วย `battery_check.h` ตัวเดียวกับ Station-Thin (เกณฑ์เดียวกันทุกตัวเลข)
เตียงส่งแรงดันมาในแพ็กเก็ตขึ้นอยู่แล้ว Host จึงเห็นแบตเตอรี่ต่ำของเตียงได้ แม้เครื่องเตียงจะเตือนที่เตียงไม่ทัน

| ที่ไหน | แสดง |
|---|---|
| หัวจอ | `!` ข้างไอคอนแบตเตอรี่เมื่อ **Host เอง** ต่ำ (เหลือง) หรือวิกฤต (แดงกะพริบ) |
| แถบล่าง | `BED 02  LOW BATT  20%` หรือ `HOST  BATT CRIT  12%` สีเหลือง/ส้ม |
| เสียง | สองครั้งทุก 5 นาที (ต่ำ) / สามครั้งทุก 1 นาที (วิกฤต) ตามระดับที่แย่สุดในบรรดา Host และเตียงที่ออนไลน์ |
| พีซี | ฟิลด์ `batLevel` ของ Host และของทุกเตียงในสถานะที่ส่งขึ้นทุกวินาที (0 ไม่มีวงจรวัด 1 ปกติ 2 ต่ำ 3 วิกฤต) |

ลำดับความสำคัญของแถบล่าง: **เหตุวิกฤตทางคลินิก > เตือนใกล้หมด > แบตเตอรี่ต่ำ > ปกติ** แบตเตอรี่ใช้เหลือง/ส้มเท่านั้น ไม่ใช้แดงซึ่งสงวนไว้ให้เหตุทางคลินิก
เสียงเตือนแบตเตอรี่เงียบเมื่อมีเหตุวิกฤตที่ยังไม่พักเสียงหรือกำลังเตือนใกล้หมด และพักเสียงด้วยปุ่มเดียวกับเตือนปกติได้
เตียงที่ออฟไลน์ไม่นับ (ระดับของมันเก่าแล้ว และมีเตือนเตียงหายอยู่แล้ว) ไม่มีวงจรวัด/ใช้ไฟ USB = ไม่เตือน

## ข้อควรรู้

- **รับเฉพาะ Station-Thin** แพ็กเก็ต Protocol v3 ถูกกรองทิ้ง ไม่ส่ง Sync แบบ v3
- จำนวนเตียงต่อเครื่องยังเป็น 8
- Host ไม่ตรวจเลขเตียงซ้ำ (ตามต้นฉบับ Host-TFT28 ที่ยังไม่มีฟีเจอร์นี้ ต่างจาก Host-OLED)
- ขณะเราเตอร์ล่ม การลองต่อใหม่ทำให้แพ็กเก็ตจากเตียงอาจหายชั่วคราว ใช้ backoff 10 วินาที → 5 นาที **ต้องวัดบนบอร์ดจริง**
- ถ้า Host ดับ จอ Station ทุกเตียงขึ้น NO HOST และไม่มีเสียงเตือนที่เตียง เพราะรหัสเตือนมาจาก Host อย่างเดียว
